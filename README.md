# Система управления пользовательскими ролями

Консольное приложение для учёта пользователей, ролей, разрешений и групп.
Реализует ролевую модель доступа (RBAC): администратор назначает роли,
объединяет сотрудников в группы и проверяет право на конкретное действие.

После ПР3 предметная область представлена **классами и объектами**.
Данные и поведение сущности хранятся вместе, а JSON используется только
для сохранения между запусками.

## Возможности
- просмотр, поиск и сортировка пользователей;
- добавление пользователя и назначение роли;
- проверка разрешения методом объекта `User` / `Role`;
- просмотр ролей и связанных разрешений;
- добавление пользователя в группу и исключение из группы;
- статистика по ролям, группам и используемым разрешениям;
- сохранение данных между запусками в JSON-файлах.

## Основные классы

### Entity
Базовый класс. Атрибуты: `id`, `name`. Метод: `__str__()`.
От него наследуют `User`, `Role`, `Group`, `Permission`.

### User — пользователь
Атрибуты: `id`, `name`, `age`, `role` (объект `Role`), `group`
(объект `Group` или `None`), `registration_date`.

Методы:
- `assign_role()` — назначить роль;
- `set_group()` — включить в группу или исключить;
- `has_permission()` — проверить право;
- `from_data()` — создать объект из JSON (`@classmethod`);
- `validate_age()` — проверка возраста (`@staticmethod`);
- `__str__()` — карточка пользователя.

### Role — роль
Атрибуты: `id`, `name`, `permissions` (список объектов `Permission`).

Методы:
- `has_permission()` — проверка по данным роли и правилу ПР1;
- `check_permission()` — правило ПР1 (`@staticmethod`);
- `access_description` — описание доступа (`@property`);
- `from_data()` — создать роль из JSON (`@classmethod`);
- `__str__()`.

### Permission — разрешение
Атрибуты: `id`, `code`, `title`. Методы: `from_data()`, `__str__()`.

### Group — группа
Атрибуты: `id`, `name`. Методы: `from_data()`, `__str__()`.

## Взаимодействие объектов
Пользователь хранит ссылки на объекты роли и группы, а не только id:

```
User
 ├── role → Role
 │            └── permissions → [Permission, ...]
 └── group → Group
```

В JSON связи по-прежнему хранятся идентификаторами (`role_id`,
`group_id`, `permission_ids`). При загрузке `storage.py` находит
объекты и передаёт их в конструкторы.
